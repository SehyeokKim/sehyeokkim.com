# 0008. 비공개 영역 로그인은 Google OIDC를 Lambda가 직접 처리하고, 허용 계정 1개만 통과

- 상태: 채택
- 날짜: 2026-10-19

## 배경

- `/private`는 사이트 주인 1명만 쓰는 구직 대시보드입니다. 회원가입은 없고, 로그인한 본인만 공고 목록을 봅니다.
- 처음 계획은 비밀번호 해시(argon2)와 로그인 시도 제한이었습니다. 하지만 비밀번호를 직접 관리하면 해시 저장, 시도 제한, 2단계 인증을 모두 직접 만들어야 하고, 실수 하나가 그대로 취약점이 됩니다.
- 사용자는 이미 2단계 인증을 켠 Google 계정이 있습니다.
- 비용 규칙상 상시 과금 리소스는 쓸 수 없습니다.

## 결정

**Google OpenID Connect(OIDC) 로그인을 Lambda(FastAPI)가 직접 처리하고, 허용된 Google 계정 1개만 세션을 받습니다.**

| 항목 | 결정 |
|---|---|
| 로그인 방식 | Google 로그인 하나. 비밀번호 로그인 없음. 2단계 인증은 Google 계정에 맡김 |
| 요청 범위 | `openid` scope만. 이메일 · 프로필은 받지 않음 |
| 위조 · 가로채기 방지 | `state`(CSRF), PKCE(`code_verifier` · S256), `nonce`(ID 토큰 재사용) 검증. 세 값은 서명한 임시 쿠키(10분, `SameSite=Lax`, `Path=/api/auth`)에 둠 |
| ID 토큰 검증 | Google 공개키(JWKS)로 서명 확인, `iss` · `aud` · `exp` · `nonce` 확인 |
| 허용 계정 | ID 토큰의 `sub`(Google 계정 고유 ID)를 SSM에 저장한 값 1개와 비교. 이메일은 바뀔 수 있어 쓰지 않음 |
| 처음 설정 | 허용 계정 값이 `UNSET`이면 로그인은 막고, 방금 로그인한 본인의 `sub`만 화면에 보여 줌 (URL에는 싣지 않음) |
| 세션 | HS256 JWT를 `httpOnly` · `Secure` · `SameSite=Strict` · `Path=/api` 쿠키로. `Max-Age`가 없는 세션 쿠키라 브라우저를 끄면 끝남 |
| 세션 연장 | 인증된 요청마다 만료를 2시간 뒤로 다시 발급. 단, 처음 로그인부터 12시간이 지나면 다시 로그인 |
| 비밀값 | Google client secret, JWT 서명 키, 허용 계정 ID는 SSM Parameter Store SecureString. 사용자가 직접 입력하고 Lambda가 실행 중에 읽음 |
| Google 쪽 | OAuth 동의 화면은 "테스트" 모드, 테스트 사용자는 본인 1명. 리디렉션 URI는 `https://sehyeokkim.com/api/auth/callback` 하나 |
| 응답 코드 | 인증 실패 · 권한 없음은 401. CloudFront가 403 · 404를 `404.html`로 바꾸는 설정이 배포 전체에 걸려 있기 때문 |
| 남용 방지 | API Gateway 요청 제한(초당 10, 순간 20). Lambda 동시 실행 상한은 계정 기본값 |

## 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| 비밀번호(argon2) + 시도 제한 (원안) | 해시 저장 · 시도 제한 · 2단계 인증을 직접 만들고 지켜야 합니다. 사용자 1명을 위해 그만큼의 공격 표면을 만들 이유가 없습니다. |
| Amazon Cognito | 관리형이라 편하지만 사용자 풀 · 앱 클라이언트 · 도메인 설정이 늘고, 사용자 1명에게는 과합니다. OIDC 흐름을 직접 구현하면 인증 동작을 설명할 수 있다는 장점도 있습니다. |
| CloudFront Functions · Lambda@Edge로 경로 보호 | 정적 파일까지 막을 수 있지만, 키를 엣지에 배포해야 하고 디버깅이 어렵습니다. 비공개 데이터는 API에서만 나오므로 API에서 막으면 충분합니다. |
| 이메일로 허용 계정 비교 | 이메일은 바뀌거나 재사용될 수 있습니다. `sub`는 계정마다 바뀌지 않는 값입니다. |

## 결과

- 비밀번호를 저장하지 않습니다. 계정 탈취 방어는 Google 2단계 인증에 맡깁니다.
- `/private`의 HTML은 공개 정적 파일이고, 공고 데이터는 로그인한 세션으로만 `/api/jobs`에서 받습니다. 화면이 보여도 데이터는 보이지 않습니다.
- 세션은 브라우저를 끄면 끝나지만, Google 로그인 상태는 브라우저에 남아 있어 다시 로그인할 때 비밀번호를 묻지 않을 수 있습니다. Google 쪽 재인증(`max_age` · `auth_time`)은 앱 인증이 필요해 보류했습니다.
- JWT 서명 키를 바꾸면 모든 세션이 끝납니다. 키가 새었다고 의심되면 SSM 값만 바꾸면 됩니다.
- API Gateway 주소(`*.execute-api.*`)로 직접 들어와도 세션 쿠키는 `sehyeokkim.com`에만 붙어 있어 인증을 통과할 수 없습니다.
